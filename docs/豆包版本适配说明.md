# 豆包版本适配说明（自己更新版本表）

## 为什么需要表

无线麦的"物理化器"用 Frida 注入豆包进程，钩住 `ImeService.exe` 里那个
低级键盘回调，把本程序注入的标记键伪装成物理按键。钩子必须知道：

| 名字 | 含义 |
|---|---|
| `callback_rva` | 键盘回调函数的起始地址 |
| `early_forward_rva` | 回调里 `call [CallNextHookEx]` 那条指令的地址 |
| `early_continue_rva` | 该指令的下一条（`call` 是 6 字节） |

另外停止录音走豆包的私有 RPC，需要校验三个文件的哈希：

| 文件 | 用途 |
|---|---|
| `doubaoime-rpc-new.dll` | 提供 `RpcPipe_SimpleMessageEx` |
| `ImeService.exe` | 服务端 |
| `tsf-oime-core.dll` | TSF 组件 |

这些地址每个版本都会变，所以作者用两张表硬编码。**表在
`apps/windows/rc003/src/ovb_rc003/doubao_rpc.py`**：

```python
_VERIFIED_IME_SERVICE_BUILDS = {
    "<ImeService.exe 的 sha256>": _DOUBAO_XXXXX_HOOK_LAYOUT,
    ...
}

_VERIFIED_VOICE_STOP_BUILDS = {
    "<rpc.dll 的 sha256>": ("<ImeService 的 sha256>", "<tsf-oime-core 的 sha256>", <stop_wparam>),
    ...
}
```

## 一条命令算出新版本的全部参数

仓库自带工具 `tools/doubao_profile.py`（仅依赖 `pefile`）：

```bat
python tools\doubao_profile.py "C:\Program Files\DoubaoIME\versions\v1.2.3"
```

输出示例（这是实测 v0.9.3.20 的结果）：

```
ImeService.exe  : 0352f9b70b33a2cde9632154435611dbea7731c85461457da143a683dae5a646
rpc.dll         : a3116866686a6c3f2b5d022ff9575ad70849899e5016d519dc5b5eb2b5bbf791
tsf-oime-core   : 984b8e80b8221ea0b659a93f5b8a396207f0e846879b135872e12a765de6c39f
CallNextHookEx  : IAT 0x1369408
candidates (3):
   callback=0x7CD5A0  forward=0x7CE5B2  continue=0x7CE5B8   layout=(8181152, 8185266, 8185272, 0, 0)
   ...
```

**原理**：解析 PE 找到 `user32!CallNextHookEx` 的 IAT 槽位，扫 `.text`
里所有 `FF 15` 指向该槽位的调用，再以 `push r12..r15` 序列为锚点、回溯到
int3 填充边界，得到函数起点。已验证能精确复原 `v0.9.3.20` 和 `v1.0.0.23`
两个版本的官方表项：

```
v0.9.3.20  -> (8181152, 8185266, 8185272, 0, 0)   实测一致
v1.0.0.23  -> (8248720, 8253853, 8253859, 0, 0)   实测一致
```

## 怎么挑正确的那一行

`candidates` 一般有 3 条，只有一条是真正的键盘回调。判断方法：

1. 取 `callback` 最小的那条（键盘回调通常在靠前的代码段）
2. 或者用 `--expect` 验证：如果你知道旧版本的 RVA 规律，可以对比
3. 实在不确定，三条都加进表里试，能触发就是对的（表是按哈希索引的，
   同一个 `ImeService.exe` 哈希只能对应一个布局，所以要挑一条）

## 推荐流程：不重新编译（改 JSON + 重启）

程序启动时会读取 `%LOCALAPPDATA%\RemoteMic\RC003\doubao_profiles.json`
（其次读 exe 同目录），把里面的条目合并进内置表。所以适配新版本只需要：

```bat
双击  适配新豆包版本.bat
```

它等价于：

```bat
python tools\adapt_doubao.py --json "%LOCALAPPDATA%\RemoteMic\RC003\doubao_profiles.json"
```

然后**重启"无线麦"**即可，无需重新构建。JSON 结构：

```json
{
  "ime_builds": {
    "<ImeService.exe sha256>": {
      "layout": [callback, forward, continue, 0, 0],
      "sig0": "40 55 56 57 ...",
      "sig1": "FF 15 ..."
    }
  },
  "voice_stop_builds": {
    "<rpc.dll sha256>": ["<ImeService sha256>", "<tsf-oime-core sha256>", 1]
  }
}
```

文件损坏或不合法时会被整段忽略，程序退回内置表继续启动。

## 另一条路：写进源码（需要重新编译）

适合要分发给别人的场景：

1. 让豆包升级到新版本，记下目录，例如 `v1.2.3`
2. 跑 `python tools\doubao_profile.py "...\v1.2.3"`，记下三个哈希和 layout
3. 或者直接 `python tools\adapt_doubao.py --write` 让它自动改 `doubao_rpc.py`
4. 在 `doubao_rpc.py` 里：
   - 加常量 `_DOUBAO_123_HOOK_LAYOUT = ("<callback>", "<forward>", "<continue>", 0, 0)`
   - 在 `_VERIFIED_FORWARD_ONLY_SIGNATURES` 里加一条（可选，仅用于字节级校验）
   - 在 `_VERIFIED_IME_SERVICE_BUILDS` 里加 `"<ImeService sha256>": _DOUBAO_123_HOOK_LAYOUT`
   - 在 `_VERIFIED_VOICE_STOP_BUILDS` 里加 `"<rpc.dll sha256>": ("<ImeService sha256>", "<tsf sha256>", 1)`
     （`stop_wparam` 新版本一般仍是 `1`；若停止无效可试 `0`）
4. 重新构建（`build.bat` 或 PyInstaller），或先把 `.py` 直接替换到
   `程序文件\ovb_rc003\` 下同名模块（把对应 `.pyd` 改名禁用）快速验证
5. 验证：按语音键说话 → 再按一次 → 豆包语音条收起

## 验证是否已支持（不用改代码）

```bat
python -c "import sys; sys.path.insert(0,'src'); from ovb_rc003 import doubao_rpc as d; print(d._verified_voice_stop_build(d._resolve_rpc_dll_path()))"
```

打印 `True` = 当前运行的豆包版本已被支持。

## 注意

- 表是按**文件哈希**索引的，豆包热修复/重装导致哈希变化也要重新加
- `_VERIFIED_FORWARD_ONLY_SIGNATURES` 里的字节串是精确匹配，跨版本必然不中，
  只用于在已识别版本上做一次快速反查；真正的定位靠 `tools/doubao_profile.py`
- 如果新版豆包改了回调的内部结构（不只是地址变化），RVA 扫出来了也可能
  触发失败，这时才需要真正逆向着色；到那一步再评估
